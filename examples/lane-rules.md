## Lane and process rules (shared)
- You share the simulator lane with another FieldApp worker. Before any boot, message the lead "<CARD> wants the lane: <plan, minutes>" and wait for its go. Wait in poll loops of at most 3 minutes (messages reach you only between commands); never wait by ending your turn. Do not compile while another worker holds the lane; compile only in your own slot or when the lead says, after a separate `uptime` check under 30.
- FieldApp's nightly CI runs about 01:00 to 03:40 local and takes the lane then. StudyApp's nightly is dispatched between 06:10 and 06:30 local and runs to about 07:00. These windows are fixed: be off the simulator (erased) from 00:50 and from 06:00 until the run has appeared AND finished. No run listed by `gh run list` at the start of a window is not a skip; a run counts as skipped only after 02:00 (FieldApp) or 06:45 (StudyApp) with none listed.
- Code-review first: when your code is written and compiles (generic iOS Simulator destination, no boot), message the lead the commit so a reviewer reads it before your first lane slot.
- Each new test shown failing on old code (record `git diff --stat` in that log); no fixed waits; no retries. Print `git rev-parse HEAD` at the top of every log. Check every claim against the pictures before you write it.
- Staged cold start: boot alone, wait for load under 15, build-for-testing -jobs 4, wait for load under 15 again, then test. One simulator at a time; shut down by UDID only (never `simctl shutdown all`); macstop.sh and `df -g /System/Volumes/Data` every 2 minutes (stop under 21 GB; first 5 minutes after a boot not counted); copy each xcresult out before a rerun; erase at the end of each slot. For picture runs on the Duo or iPad use `FLD_GRANT_LOCATION=1` (scripts/ui-tests.sh) so the first-run location alert never shows.
- The whole iPhone 17 UI suite once at the final commit if your change touches lines a phone runs (ask the lead first; never twice for one commit). The repo's Duo check applies: each pose's affected tests, pictures read, poses named in the PR.
- Repo text says what the change does; investigation figures go in the hand-back. `git status` before every commit; one git command per call. If git push hangs 60 s, stop and tell the lead. Do not push or open a PR until the lead says.
